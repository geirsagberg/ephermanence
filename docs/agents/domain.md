# Domain docs

This repository has a single domain context.

Before exploring a feature, read the root `GLOSSARY.md` if present and relevant ADRs
in `docs/decisions/`. Continue silently when a document is absent; create domain
documents only when terms or decisions need to be recorded.

Use the glossary's vocabulary in specs, tickets, code, and tests. Surface conflicts
with accepted ADRs instead of silently overriding them. Record new ADRs alongside
the existing decisions in `docs/decisions/`.
